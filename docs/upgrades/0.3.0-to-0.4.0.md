# Upgrade @arki/failure 0.3.0 to 0.4.0

Nobody has to change code: 0.4.0 only adds `isFault`. Read on if you mark telemetry spans as errors for returned failures.

## What changed

- New `isFault(failure)`. It is true when a returned failure is something an operator must act on: its `status` is 500 or higher, such as a provider outage, a wrong setting or `UnexpectedDefect`. It is false for outcomes the caller handles, such as a declined card or a missing record (4xx). A definition with no `status` defaults to 400, so it is not a fault. Telemetry code can always record `failure.code` and mark a span as an error only when `isFault(failure)` is true.

## Public API changes

Added:
- `isFault` from `@arki/failure` (function)

## Steps

1. Bump the dependency: `"@arki/failure": "^0.4.0"`.
2. Optional: where you mark a span as an error for every returned failure, mark it only for faults.

   Before:

   ```ts skip="fragment: inside your own traced call, with its span and result"
   if (isFailure(result)) span.setStatus({ code: SpanStatusCode.ERROR });
   ```

   After:

   ```ts skip="fragment: inside your own traced call, with its span and result"
   if (isFailure(result)) {
     span.setAttribute('failure.code', result.code);
     if (isFault(result)) span.setStatus({ code: SpanStatusCode.ERROR });
   }
   ```

## Verify

`bun pm ls @arki/failure` prints `@arki/failure@0.4.0`, and your typecheck passes.
